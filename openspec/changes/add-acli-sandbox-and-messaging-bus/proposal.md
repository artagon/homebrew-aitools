# Proposal: Unified Sandboxed AI CLI Launcher (`acli`), Shared Nix VM, Inter-Agent Bus, and Tap Packaging

## Why

Managing nine heterogeneous AI coding CLIs (`claude`, `codex`, `agy`, `copilot`, `kimi`, `grok`, `opencode`, `gemini`, `qwen`) across macOS and Linux currently relies on four drifting wrapper catalogs, slow shell-based option translators (`180–309 ms` under macOS Endpoint Security), inconsistent or absent inner OS sandboxes, `20 s` polling loops over a single shared AgentMail writer token, `~500 MiB` of per-pane Node `mcp-remote` bridges, and fragmented shell/Python hook telemetry with exfiltration risks. Introducing `acli` (`acli`, `aclid`, `acli-shim`) with default host OS kernel sandboxing, a single shared warm `libkrun` Nix VM for autonomous `--mode yolo` swarms, a zero-pane-polling 3-plane messaging bus (`NATS` + `AgentMail` + dual-engine `Beads` `br v0.7.6` & `bd v1.3.4`), broker-terminated zero-exfiltration production telemetry (`artagon-harness-eval` 4-layer store + `0600` `otlp-ring`), and hardened `artagon/aitools` Homebrew + Split-System Nix packaging eliminates drift, closes sandbox-escape vectors, and cuts interactive latency and memory overhead simultaneously.

## Out of Scope

- Replacing upstream coding CLI binaries or maintaining long-term downstream forks of `mcp_agent_mail_rust`, `nats-server`, `libkrun`, `herdr`, or `ntm`.
- Packaging third-party NATS MCP wrappers (`mcp-nats`) or running competing local message brokers (`hcom`, `herdr-message`, `autoswarm`, `cao-ops`, `Zenoh`, `Cairn`) as default runtime buses.
- Multi-host WAN federation, cross-organization A2A/SLIM/ANP meshes, or cloud-hosted remote sandbox backends.
- Automatic mutation of live user dotfiles (`~/.claude*`, `~/.codex*`, `~/.config/*`, `~/.homebrew/trust.json`, `~/.sigstore`) during Homebrew install, upgrade, or automated test runs.
- Running macOS-only GUI/SDK builds (`xcodebuild`) inside the Linux `libkrun` VM; those remain on default host `os-sandbox`.
