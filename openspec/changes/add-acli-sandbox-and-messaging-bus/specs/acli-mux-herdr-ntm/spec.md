# Spec Delta

## Purpose

Defines the dual-channel `acli-mux/v1` PTY (single-use `52 B` `ACLIMUX1` preamble + `64 KiB` ring / `256 KiB` credit window + allowlist outbound VT filter on `--vm`, host PTY relay, and TTY Supervised pumps) and boot-latched `[u32 len][12B pane_id][u8 type][payload]` supervisor control (`envp` `ACLI_SUPERVISOR_KEY`, bounded VM recycle `exit 70` on corrupt outer envelopes, typed `0x07 InjectPromptReq`/`0x08 InjectPromptAck` with queued human stdin, full `written_char_len` provider cancel + verified `composer_empty`, complete ECMA-48 quarantine tokenizer + out-of-band `acli pane release <pane_id>`, and `60 s` `req_id` deduplication, OS sleep-paused clocks), priority-ordered 9-state FSM (wired to Mode A/B `429` and `telem.sock` hooks), `aclid`-owned `HERDR_SOCKET_PATH` protocol-22 push with live token/TTFT/bead metadata and reconnect replay, and `tmux`/`ntm` compatibility.

## ADDED Requirements

### Requirement: Dual-Channel acli-mux/v1 Single-Use PTY Preamble and Framed Supervisor Envelope
`acli` and `acli-guest-supervisor` (PID 1 launched by `acli-shim`) MUST separate per-pane PTY data (`vsock:5101`) from boot-latched control (`vsock:5102`). `vsock:5101` MUST consume a single-use `52 B` `ACLIMUX1` preamble (`<= 2000 ms`) with an allowlist outbound VT filter (shared with host PTY relay and TTY Supervised pumps); `vsock:5102` MUST authenticate via `krun_set_exec` `envp` `ACLI_SUPERVISOR_KEY` and use `[u32 len][12B pane_id][u8 type][payload]` (`<= 64 KiB`).

#### Scenario: Single-use ACLIMUX1 token, separate ring/credit bounds, and allowlist outbound VT filter
- **WHEN** eight concurrent panes open `vsock:5101` in reverse order on a `--vm-memory 10240` VM, a duplicate retry presents an already-consumed `pty_stream_token`, or a `--vm`, host PTY-relayed, or partial-TTY Supervised pane emits `DSR` (`CSI 5n`/`6n`), `DECRQM`, `XTWINOPS`, `XTVERSION`, `DA`, `OSC 4/8/10/11/12/50/52/1337`, `DCS` (`XTGETTCAP`, `DECRQSS`, tmux passthrough), `APC`, `PM`, or `SOS`
- **THEN** `aclid` atomically consumes `pty_stream_token` on first valid bind (`b"ACLIMUX1" (8 B) || pane_id (12 B) || pty_stream_token (32 B)` within `2000 ms`), rejects duplicate/replayed binds without disturbing the active stream, and runs per-pane bounded I/O (`64 KiB` per-pane PTY ring buffer separate from the `256 KiB` `vsock` flow-control credit window)
- **AND** host `acli` (`--vm` client, host PTY relay, and partial-TTY Supervised pumps) enables `cfmakeraw()` with RAII `termios` restore on PTYs; BOTH Interactive PTY Relay `(a)` AND the `--vm` interactive client send one pre-launch `CSI 6n` to the host terminal (`100 ms` timeout, falling back to row `1`, col `1`) to seed virtual cursor state before spawning the child, and intercept `CSI 5n` (replying `CSI 0 n`), `CSI 6n` (replying from virtual cursor state), and primary `DA` (`CSI c` / `CSI 0 c`, replying fixed `CSI ? 62 ; 22 c`) locally without ever forwarding `DSR` or `DA` to the host terminal; the shared **allowlist** outbound VT filter permits ONLY exact `(prefix, intermediate, final)` tuples: UTF-8 printable text, C0 `BEL` (`0x07`)/`BS`/`HT`/`LF`/`CR`, 2/3-byte escapes `ESC 7`/`ESC 8`/`ESC M`/`ESC =`/`ESC >`/`ESC ( B`, CSI with `prefix=""` & `intermediate=""` and final in `@ABCDEFGHJKLMPSXZbdfgmrs` (`i` Media Copy removed; `n` answered locally or dropped, never forwarded; non-private `h`/`l` dropped), CSI `prefix=""` & `intermediate=SP` & `final="q"` (`CSI Ps SP q`), CSI DEC private mode `prefix="?"` & `intermediate=""` & `final="h"|"l"` restricted to modes `{1, 7, 12, 25, 1000, 1002, 1003, 1004, 1006, 1015, 1047, 1048, 1049, 2004, 2026}` (rejecting ANY CSI containing `$`, `>`, `=`, `<`, or `?` outside those listed tuples — deterministically dropping `DECRQM` `CSI ? Ps $ p`, `XTVERSION` `CSI > q`, kitty keyboard query `CSI ? u`, and `XTWINOPS`), `OSC 0`/`2` window title, and base64-set `OSC 52;<sel>;<base64>` ONLY when host-invoked `--allow-osc52` is set outside `--mode yolo` and `sys_spawn` (ALWAYS dropping `OSC 52;...;?`, `OSC 4/8/10/11/12/50/1337`, `DCS`, `APC`, `PM`, `SOS`), sets `tmux allow-passthrough off`, and delivers sibling panes' `Ctrl-C` without HoL stall

#### Scenario: Corrupt vsock:5102 outer envelope triggers bounded VM recycle with exit 70
- **WHEN** `acli-shim` launches `acli-guest-supervisor` (PID 1), a pane sends a malformed payload vs a truncated/corrupt/oversized outer envelope on `vsock:5102`, or the host wakes from laptop sleep (`> 5 s` wall-clock jump)
- **THEN** `acli-shim` passes `ACLI_SUPERVISOR_KEY` exclusively via PID-1 `krun_set_exec` `envp` (NEVER `/proc/cmdline`), `acli-guest-supervisor` zeroizes it strictly AFTER boot-latching all **three** host-initiated vsock channels — **`vsock:5040` (`aclid`), `vsock:5050` (`telem`), AND `vsock:5102` (`mux-ctl`)** — (rejecting all later `connect()` calls), well-framed pane payload errors return `PaneProtocolError{pane_id}` without dropping `vsock:5102`, and any corrupt/truncated/oversized outer envelope closes `vsock:5102` and triggers **bounded VM recycle terminating active VM panes with observable `exit 70` (`acli: error[E70:vsock_control_corrupt]:`)** (never attempting to re-authenticate the zeroized boot latch)
- **AND** `Ping`/`Pong` (`2000 ms` interval) uses OS sleep-paused clocks (Linux `CLOCK_MONOTONIC`, macOS `CLOCK_UPTIME_RAW` + `IORegisterForSystemPower`), resetting on wall-clock jumps `> 5 s` and requiring 3 consecutive misses (`6000 ms`) plus failed `acli-shim` liveness before VM recovery

### Requirement: Scoped Guest Signal Forwarding and Graceful Teardown
Host signals MUST be translated over Channel 2 (`vsock:5102`) to the target pane's guest foreground process group or session leader without terminating `aclid`, `acli-shim`, or sibling panes in the shared VM.

#### Scenario: Interactive Ctrl-C and SIGWINCH affect only the target pane
- **WHEN** a user sends `Ctrl-C` (`0x03`) or resizes the terminal (`SIGWINCH`) in Pane 1 of an active multi-pane shared VM
- **THEN** `acli` forwards `0x03` / `SendSignal(SIGINT)` to Pane 1's guest `fg_pgrp` and `ResizePty` (`TIOCSWINSZ`) on Channel 2 for Pane 1 only
- **AND** sibling panes in the shared VM continue uninterrupted

#### Scenario: Host SIGTERM or SIGHUP drains guest session with 1500 ms SIGKILL escalation
- **WHEN** `tmux kill-pane`, `herdr pane close`, or `ntm --robot-kill-agent` delivers `SIGTERM` or `SIGHUP` to host `acli` (in `--vm` or Supervised host mode)
- **THEN** `acli` (which keeps an active `SIGHUP`/`SIGTERM` handler in Supervised modes and resets child `SIGHUP` to `SIG_DFL` pre-`execve`) sends `SIGTERM`/`SIGHUP` to the pane's guest/host `session_leader`, waits up to `1500 ms` for transcript flush and `syncfs()`, escalates to `cgroup.kill`/`SIGKILL` if alive, flushes trailing PTY bytes, restores `termios`, and exits with the child exit code (`137` on cgroup OOM)

### Requirement: Priority-Ordered Nine-State Four-Sensor Pane Lifecycle FSM
`aclid` MUST track every pane using a deterministic nine-state FSM with strict priority order (`exited > hung_turn > blocked_permission > blocked_dialog > rate_limited_backoff > compacting > working_turn > starting > idle_at_prompt`), fusing four sensors (`pty_ring`, `proc_tree`, `api_inflight`, `hook_channel`) with an explicit per-mode availability contract.

#### Scenario: Conflicting simultaneous sensor events resolve by canonical priority order
- **WHEN** a `--vm` pane simultaneously has an active guest child (`working_turn`), a Mode A/B proxy HTTP `429` `Retry-After` backoff timer (`rate_limited_backoff`), and a pending Zone-3 host MCP approval (`blocked_permission`) in any event arrival order
- **THEN** `aclid` evaluates the canonical priority order and publishes `blocked_permission` deterministically (feeding Mode A/B HTTP `429` + `Retry-After` directly into `api_inflight` -> `rate_limited_backoff`)
- **AND** `hook_channel` (`telem.sock` / `vsock:5050` `< 3 ms` `acli hook emit [--drain]`, `@opencode-ai/plugin`, native OTLP, and session JSONL) supplies exact `session_id`, `turn_complete`, and live token/TTFT/tool counts while terminal-capability-gated `OSC 133`/`OSC 9;4` markers never corrupt visible prompt lines

#### Scenario: Interactive PTY-relayed vs non-PTY host panes report exact sensor provenance
- **WHEN** a user runs an interactive host `os-sandbox` pane (`isatty(0) && isatty(1)`, Supervised PTY relay via `<ACLI_RUN_DIR>/p/<pane_id>/pty.sock`) versus a partial-TTY Supervised pump or pure non-TTY Fast-Exec host pane
- **THEN** interactive host `os-sandbox` supplies exact `pty_ring` sensors (DECSET `2004`, prompt glyph, `host_stdin_idle`, `pane_input_epoch`, echo) plus `hook_channel` (`telem.sock`) while reporting `null`/`unavailable` for VM-only fields (`cgroup_memory_bytes`, unproxied `api_inflight`)
- **AND** non-PTY host panes pre-register `<ACLI_RUN_DIR>/p/<pane_id>/meta.json` pre-exec and report `pty_ring` as `unavailable` (using Path B/C wakeups only)

### Requirement: aclid-Owned Zero-Patch herdr Protocol-22 Push Authority with Reconnect Replay
When `HERDR_SOCKET_PATH` and `HERDR_PANE_ID` are present, `aclid` MUST be the sole owner of the `herdr` socket connection, `server_epoch`, protocol-22 JSON-RPC reports (`pane.report_agent_session`, monotonic-`seq` `pane.report_agent`, `pane.report_metadata` with live token/TTFT/bead telemetry, `pane.release_agent`), and reconnect snapshot replay across both host and `--vm` panes.

#### Scenario: aclid replays blocked snapshot across herdr restart even after Fast-Exec Launch
- **WHEN** the `herdr` daemon disconnects and restarts while a `--vm` or already-`exec`'d Fast-Exec host pane is in `blocked_permission`
- **THEN** `aclid` maps `idle_at_prompt -> idle`, `starting | working_turn | compacting -> working`, `blocked_permission | blocked_dialog | rate_limited_backoff | hung_turn -> blocked`, and `exited -> pane.release_agent`, and publishes live per-pane `{tokens_in, tokens_out, cache_read_tokens, ttft_ms, tool_calls, bead_id, epic_id}` and daemon `telemetry_health` via `pane.report_metadata` and `acli ps --json`
- **AND** upon reconnect, `aclid` registers a fresh `server_epoch`, replays the full current state snapshot (`blocked`) before subsequent deltas, and rejects stale-epoch reports without halting any pane

### Requirement: Typed Ordered InjectPrompt with Provider Reset, Verified composer_empty, and tmux/ntm Identity
`acli` and `aclid` MUST identify panes by non-recycling `12`-char CSPRNG `pane_id` (`^[a-z0-9]{12}$`), serialize automated `InjectPrompt` + `Enter` via `vsock:5102` `0x07`/`0x08` (or `pty.sock`) while queueing human stdin during the `<= 25 ms` settle window, cancel full `written_char_len` + verify `composer_empty`, expose out-of-band `acli pane release <pane_id>`, cache `req_id` for `60 s`, never send automated `Enter` over stock `tmux`, and expose provider identity.

#### Scenario: Provider non-0x03 line-cancel, UTF-8-safe ECMA-48 quarantine, 0x09 PaneRelease, and 60 s req_id cache
- **WHEN** `aclid` sends `vsock:5102` `frame_type = 0x07` (`InjectPromptReq{req_id, expected_epoch, ttl_ms, ascii_trigger}`) to `acli-guest-supervisor` (or equivalent to host `pty.sock`) while (a) human stdin arrives during the `<= 25 ms` settle window (including delayed or partial echo where `echoed_len == 0`), (b) the provider adapter lacks deterministic line-reset or `composer_empty` verification fails within `50 ms`, OR (c) a duplicate/retried `req_id` arrives in-flight or after `Submitted` within `60 s`
- **THEN** `ACLIIDX1` requires every provider line-cancel/erase sequence to **exclude `0x03`** (rejected at index load with `exit 9`), the PTY owner preflights `ACLIIDX1` reset capability BEFORE typing (falling back to non-submitting durable `Queued` + `Attention` for providers lacking deterministic reset or un-relayed `--isolation host` without Supervised flags), processes `InjectPromptReq` on the single-threaded PTY loop, rejects payloads with `ESC`, `0x9B`, `DEL`, C0 (other than `LF`/`TAB`), C1, BiDi overrides, or `\x1b[200~`/`\x1b[201~`, verifies `idle_at_prompt`, pinned prompt glyph, DECSET `2004`, `composer_empty`, `host_stdin_idle >= 1500 ms`, `ttl_ms` unexpired, and `expected_epoch`, writes the bracketed-paste trigger, confirms echo with unchanged `pane_input_epoch`, writes `\r` (`enqueue_latency < 1 ms`; `submit_latency <= 25 ms`), and caches + replies `0x08 InjectPromptAck{req_id, status: Submitted, epoch}` for `60 s`
- **AND** in race (a), while `InjectPromptReq` is in flight, the PTY owner holds newly arriving human stdin bytes in a memory queue, aborts `\r`, emits the provider's `ACLIIDX1`-declared non-`0x03` line-cancel/erase sequence covering the **full `written_char_len`** of the written trigger (NOT `echoed_len`), verifies `composer_empty == true` within `50 ms`, flushes the queued human bytes byte-for-byte without mixing human and automated text, and replies `AbortedEpoch`; if `composer_empty` is still false after `50 ms` post-write (case b), the PTY owner sends non-`0x03` line-cancel ONCE more (`<= 50 ms`) and, if still unverified, does NOT submit and does NOT flush buffered human bytes into the dirty composer — setting `path_a_quarantined = true`, replying `AbortedGuard`, raising `Attention`, printing one out-of-band host status notice, and **continuously parsing host `stdin` across read boundaries with a complete stateful ECMA-48 / `DECSET 2004` sequence tokenizer without stalling**: (1) **rule (1) takes strict priority over `orphan_paste_open` for `0x03` whenever `path_a_quarantined == true`, and whenever `orphan_paste_open == true` BOTH rule (1) and the post-quarantine `orphan_paste_open` window require a standalone 1-byte `stdin` read bounded by `>= 50 ms` host `stdin` idle both before and after to treat `0x03` as standalone `Ctrl-C` (dropping any `0x03` arriving in a multi-byte read or without both `>= 50 ms` idle margins as late paste tail bytes without forwarding or discarding held bytes)**: the first standalone `Ctrl-C` (`0x03` strictly in `tokenizer_state == Ground`, NEVER inside a bracketed paste or `paste_tail_discard`, and passing the 1-byte + `>= 50 ms` idle check whenever `orphan_paste_open == true`) forwards `0x03` once, atomically discards all held frames/bytes, and runs a non-`0x03` `ACLIIDX1` erase + `composer_empty` verification check — **EVERY subsequent standalone `0x03` in `Ground` while `path_a_quarantined == true`** is **consumed by the PTY owner (NOT forwarded)** and prints a host hint pointing to **`acli pane release <pane_id>`** so the child CLI never exits from quarantine recovery; manual quarantine override when `composer_empty` has a persistent false negative is strictly **out-of-band** via host CLI **`acli pane release <pane_id>`** (routed directly over `ctl.sock` for host panes and via `acli-mux/v1` **`0x09 PaneRelease` / `0x0A PaneReleaseAck`** frames on `vsock:5102` for `--vm` panes), which **atomically discards all remaining held bytes (returning `discarded_bytes: u32`), resets `tokenizer_state = Ground`, AND resets `orphan_paste_open = false`** BEFORE clearing `path_a_quarantined = false` and prints a host notice without sending `0x03` to the child; (2) standalone `Escape` (`0x1b` strictly in `Ground`) forwards **after** a configurable inter-byte disambiguation window (default `25 ms`) with zero continuation bytes, discards held units, re-runs non-`0x03` erase + verify once, and drops any late CSI/SS3 continuation arriving within a `100 ms` post-ESC grace window; #### Scenario: Accurate tmux pane_current_command truth and stock ntm compatibility
- **WHEN** unmodified `tmux` / `ntm` or `acli ps --json` inspects interactive `os-sandbox` panes and `--isolation host` native or Node (`gemini`, `qwen`) panes
- **THEN** `acli` documents and maintains exact process-name truth (`#{pane_current_command}` is `acli` on interactive `os-sandbox` relay, `<provider>`/XNU `p_comm` on `--isolation host` native binaries, and `node` on `gemini`/`qwen`), exports `ACLI_LOGICAL_PROVIDER` in `meta.json`, stamps `@acli_provider` on the `tmux` pane before handoff, and routes `acli` diagnostics away from robot-facing PTY output
