# Spec Delta

## Purpose

Defines broker-terminated, zero-exfiltration production telemetry across all nine agent CLIs (`claude`, `codex`, `gemini`, `qwen`, `opencode`, `copilot`, `kimi`, `grok`, `agy`): dedicated per-pane `ACLI_TELEM_TOKEN`, read-only per-pane plugin/config staging, per-tier `telem.sock`/chunked `vsock:5050`/dual-stack macOS TCP `localhost:<aclid_otlp_port>` transport, `< 3 ms` Rust `acli hook emit [--drain]` with two-step `0x81`/`0x82` Path B acks and content-free host fallback, 9-CLI trap normalization, closed positive attribute allowlist + 4-stage pre-write Rust DLP, 6-plane W3C `traceparent`/`SpanLink` stitching, core pure-Rust Dual-Sink fanout (`traces/*.json` + Parquet + SQLite + `0600` `otlp-ring` / collector-only RAM audit queue), and `acli telemetry` operator CLI.

## ADDED Requirements

### Requirement: Broker-Terminated Zero-Exfiltration Telemetry Transport and Dedicated ACLI_TELEM_TOKEN
Sandboxed host (`--isolation os-sandbox`) and `--vm` panes MUST hold zero external OTLP sockets/creds, authenticating telemetry + same-pane content-free Path B `0x81`/`0x82` ONLY via dedicated `256-bit` `ACLI_TELEM_TOKEN` (`!= ACLI_BUS_TOKEN`, zero other bus authority). Streams/hooks MUST terminate in host `aclid` via `telem.sock`, chunked `vsock:5050`, or macOS TCP `localhost:<aclid_otlp_port>` (accepted residual: best-effort vs same-UID downtime port-squatter; `telem.sock` preferred).

#### Scenario: Dedicated ACLI_TELEM_TOKEN, per-tier routing, chunked vsock:5050, and dual-stack macOS OTLP bind
- **WHEN** any of the nine CLIs emits native OTLP or hook events inside (a) shared `libkrun` `--vm` (`--mode yolo`), (b) Linux host `os-sandbox`, or (c) macOS host `os-sandbox` (`Seatbelt`), or a pane presents `ACLI_TELEM_TOKEN` on `bus.sock` or `ACLI_BUS_TOKEN` on telemetry endpoints
- **THEN** `aclid` mints a distinct `64`-hex `256-bit` CSPRNG **`ACLI_TELEM_TOKEN`** per pane authorizing **solely** telemetry ingestion (`telem.sock`, `vsock:5050`, macOS OTLP HTTP `Authorization: Bearer <ACLI_TELEM_TOKEN>`) plus **same-pane content-free Path B wakeup drain/ack (`0x81`/`0x82`) ONLY** (zero cross-pane, mail-body, bead, reservation, or git authority), rejecting `ACLI_TELEM_TOKEN` on `bus.sock` and rejecting `ACLI_BUS_TOKEN` on telemetry endpoints (`HTTP 401` / frame reject); panes NEVER stage `otel.jsonl` files on disk
- **AND** in (a) `--vm`, `acli-guest-supervisor` (`GuestSupervisor`) executes its `AwaitingThreeChannelBootLatch` exit action to zeroize `ACLI_SUPERVISOR_KEY` in guest RAM strictly AFTER boot-latching all three host-initiated channels (`vsock:5040`, `vsock:5050`, `vsock:5102`); `/run/acli/p/<pane_id>/telem.sock` (`0600`, bind-mounted ONLY into that pane's `bwrap` mount ns) and a per-pane `bwrap(CLONE_NEWNET)` `127.0.0.1:<ephemeral>` forwarder (`http/protobuf`, `http/json`, `grpc`) stream through `acli-guest-proxy` (which verifies per-pane `ACLI_TELEM_TOKEN` before multiplexing) over `vsock:5050` using **`<= 64 KiB` (`65,536 B`) multiplexed chunks** (`magic: "AT50"`, `pane_id_12`, enumerated `signal_type`: `0x01 Traces`, `0x02 Metrics`, `0x03 HookEvent`, `0x04 Logs`, `0x81 HookDrainResp`, `0x82 HookDrainAck`, dropping any unknown `signal_type` frame with `acli_telemetry_invalid_signal_total`, `flags`, `req_id: u32`, `chunk_idx: u16`, `chunk_total: u16`, `chunk_len: u32`, capping concurrent `AT50` reassemblies at `<= 8 / pane` with `5 s` timeout and unified `<= 5 MiB` compressed / `<= 16 MiB` decompressed logical payload across `--vm` and host) scheduled via per-pane round-robin fair queueing inside an independent `512 KiB` window (decoupled from `5101`/`5102`/`5040`) with strict priority for `0x03`/`0x81`/`0x82`; host `aclid` drops/rejects invalid per-pane tokens per `(pane_id, req_id)` (`acli_telemetry_auth_rejected_total`, rate-limiting per-pane auth rejects) **without** closing shared `vsock:5050`, closing `vsock:5050` (and setting `telemetry_health = "degraded"` without post-zeroization key re-auth) **strictly** on outer proxy frame corruption (`magic != "AT50"` or `chunk_len > 65536`)
- **AND** in (b) Linux host `os-sandbox`, `<ACLI_RUN_DIR>/p/<pane_id>/telem.sock` (`0600`, `sun_path <= 103 B`, bind-mounted into `bwrap`) plus an in-netns `127.0.0.1:<ephemeral>` -> `telem.sock` relay (`< 256 KiB`) run under `bwrap --unshare-net` (`slirp4netns --disable-host-loopback`) keeping host `127.0.0.1:{4222,8765,8090}` 100% unreachable, authenticated via `SO_PEERCRED` + constant-time `Authorization: Bearer <ACLI_TELEM_TOKEN>`
- **AND** in (c) macOS host `os-sandbox`, `<ACLI_RUN_DIR>/p/<pane_id>/telem.sock` is allowed via `(allow network-outbound (literal (param "PANE_TELEM_SOCK")))` (preferred transport on macOS); when `ACLI_TELEMETRY=otlp`, `aclid` persists `<aclid_otlp_port>` in per-instance `daemon.json` (`!= runtime nats_port, agentmail_port, gateway_port`), MUST exclusively bind **both `127.0.0.1:<aclid_otlp_port>` AND `[::1]:<aclid_otlp_port>`** (`IPV6_V6ONLY=1`, without `SO_REUSEPORT`) BEFORE launching panes, passes explicit `http://127.0.0.1:<aclid_otlp_port>` to macOS pane SDKs, and grants strictly TCP-narrowed **`(allow network-outbound (remote tcp "localhost:<aclid_otlp_port>"))`** (with `network-inbound`/`network-bind` denied, keeping `:4222/:8765/:8090` and all other loopback ports `EPERM`); on normal `aclid` restart on macOS, `aclid` **NEVER rotates surviving live panes' `ACLI_TELEM_TOKEN` or `fallback_mac_key`** (because already-running panes have immutable `envp` and read-only per-pane `config.toml`; `aclid` preserves each surviving live pane's `sha256_telem_token` and `fallback_mac_key` across restarts so `telem.sock` `0x03 HookEvent`, `SessionStart` unread recovery, Path B `0x81`/`0x82` `--drain`, `hooks-fallback.jsonl`, and OTLP continue without `401` breakage, minting fresh CSPRNG `ACLI_TELEM_TOKEN`s **only for newly spawned panes**; accepted residual: macOS loopback TCP HTTP OTLP is best-effort against a same-UID unsandboxed host port-squatter during unmanaged `aclid` downtime, with `telem.sock` UDS preferred wherever supported), binds the persisted `<aclid_otlp_port>` on both stacks, and if either bind fails on first start or restart marks `telemetry_health = "degraded"`, **disables/revokes ONLY HTTP OTLP ingress** (keeping `telem.sock`, `fallback_mac_key`, and Path B `--drain` valid with the surviving pane's existing token!), and does NOT reallocate a different port for running panes or emit the SBPL TCP rule for new panes

### Requirement: Sub-3ms Rust acli hook emit Fast Path, Two-Step Path B Receipt, and Nine-CLI Normalization
`acli` MUST provide `< 3 ms` p99 non-perturbing `acli hook emit --cli <provider> --event <canonical_event> [--ack none|agy-noop|empty-json] [--drain]` over `telem.sock` (`ACLI_TELEM_TOKEN`), with two-step `0x81 HookDrainResp`/`0x82 HookDrainAck` pipe-handoff Path B receipts and `blake3::derive_key` `fallback_mac_key` content-free host fallback. `ACLIIDX1` MUST normalize all nine CLIs' OTel flags, 11 canonical hook events, RO per-pane plugin/config staging, and live vendor traps.

#### Scenario: Sub-3ms hook emit, two-step 0x81/0x82 Path B pipe-handoff ack, and restart-verifiable fallback_mac_key
- **WHEN** a CLI triggers a hook running `acli hook emit --cli <provider> --event <canonical_event> [--ack none|agy-noop|empty-json] [--drain]`, including during a host `aclid` restart, on a `--vm` `telem.sock` failure, or when `stdin` exceeds `1 MiB`
- **THEN** `acli hook emit` ignores `SIGPIPE`, arms a `400 ms` monotonic watchdog (`_exit(0)` after emitting any required `--ack` bytes), drains `fd 0` to `EOF` (parsing the first `<= 256 KiB` and discarding excess bytes up to the watchdog so CLIs writing `> 1 MiB` never see `EPIPE`), extracts `(session_id, turn_id, tool_name, tool_use_id)` plus `TRACEPARENT`/`COPILOT_TRACEPARENT` without regexes, checks `ACLIIDX1` `supports_hook_context_injection: bool` per `(provider, hook_event)` (`true` only on verified context-injecting hooks for `claude`, `gemini`, `qwen`, `opencode`; `false` on `copilot` `preToolUse`, `agy` `--ack agy-noop` `{}`, and `codex`/`kimi`/`grok`, omitting `DRAIN_WAKEUPS` when `false`), and sends `0x03 HookEvent` authenticated by `ACLI_TELEM_TOKEN` within `250 ms`
- **AND** when `DRAIN_WAKEUPS` is set, `aclid` replies `0x81 HookDrainResp {req_id, delivery_batch_id, wakeups[]}` while holding JetStream messages in `PENDING_DELIVERY_ACK` (`AckWait = 5 s`); `acli hook emit --drain` writes + flushes the provider-specific JSON wrapper (`additionalContext` / `hookSpecificOutput.additionalContext`) to `stdout` and **ONLY after `stdout` flush succeeds** sends `0x82 HookDrainAck {req_id, delivery_batch_id}` before `exit 0`; `aclid` acknowledges JetStream **solely** upon receiving `0x82 HookDrainAck` (which attests **hook-stdout pipe handoff** to the parent CLI — if the CLI exits before reading its hook pipe, automatic next-turn recovery of unread mail is scoped **strictly to surviving registrations of the same pane** [`aclid` F1 restart or CLI restart inside the same `herdr`/`tmux` pane retaining `<agent_name>` and `registration_min_msg_id`]: `aclid` persists monotonic per-pane **`session_seq: u64`** in `panes-registry.json`, incrementing `session_seq` and clearing prior-session Path A mail suppression on each verified CLI process generation / `SessionStart` (`0x03 HookEvent` with `event == "SessionStart"`) / CLI respawn inside the same registered `<pane_id>` [so Path A keys mail duplicate suppression by **`(kind="mail", session_seq, mail_epoch, max_id)`**], and executes an **authorized post-floor unread-level check** for `(project_key, agent_name)` [`read_ts IS NULL AND msg.id > registration_min_msg_id` via RO SQLite under `schema_ok`, or `fetch_inbox(agent_name, unread_only=true, mark_read=false)` under `!schema_ok`, gated by `!epoch_rebind_pending && !unverified_store_restore`] — when `unread > 0`, immediately returning the reminder directly in `SessionStart`'s `0x81 HookDrainResp` [when `supports_hook_context_injection == true`, held until `0x82`] OR enqueuing a per-session wakeup [`Nats-Msg-Id: sess:<proj_hash>:<pane_id>:<session_seq>:e<mail_epoch>:<max_id>`] for `2 s` idle Path A / Path C `bus_wait` delivery, whereas once the pane exits and is reaped, unread messages addressed to the retired `<agent_name>` surface to `coordinator` or the human operator via `acli msg status` and host-only `acli msg inbox --agent <retired_agent>`; on socket EOF, lost reply, or watchdog timeout, `acli hook emit` still writes safe `--ack` JSON and exits `0`, leaving wakeups pending for redelivery)
- **AND** at pane spawn, `aclid` derives a one-way domain-separated `256-bit` PRF **`fallback_mac_key = blake3::derive_key("acli 2026 hook-fallback-mac v1", ACLI_TELEM_TOKEN.as_bytes())`** (which **cannot** authenticate live `telem.sock` or OTLP requests) and persists `fallback_mac_key` alongside `sha256_telem_token` in `0600` `panes-registry.json` (**preserving both `sha256_telem_token` and `fallback_mac_key` intact across normal `aclid` restarts for surviving live panes**, minting fresh tokens only for newly spawned panes); on host `os-sandbox`/`host` ONLY (NEVER in `--vm`, where `telem.sock` failure writes safe `--ack` and exits `0`), if `telem.sock` returns `ENOENT`/`ECONNREFUSED`, `acli hook emit` derives the identical `fallback_mac_key` from `ACLI_TELEM_TOKEN` and writes **ONLY a fixed-schema content-free counter record** (`<= 512 B/line`: `{schema: "acli-hook-fallback/v1", seq: "(ts_unix_ns, pid)", ts_unix_ns, pane_id, event_enum, provider_enum, tool_category_enum, duration_ms, exit_code, hmac_sha256}` keyed with `fallback_mac_key` — zero raw `stdin`, prompts, tool args/results, file paths, or free-form strings) via `openat(pane_tmp_dirfd, "hooks-fallback.jsonl", O_WRONLY|O_CREAT|O_APPEND|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC, 0600)` after verifying `S_ISREG`, `st_nlink == 1`, and **`st_size + line_len <= 1 MiB` (`1,048,576 B`)**; on restart/recovery, `aclid` immediately validates and consumes `hooks-fallback.jsonl` without waiting for pane reconnect via `openat(pane_tmp_dirfd, "hooks-fallback.jsonl", O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC)`, verifying `fstat` `S_ISREG`, matching `st_uid`, and `st_nlink == 1` (unlinking refused non-regular/foreign/multi-link files with `acli_telemetry_fallback_refused_total`), **validating and ingesting complete `<= 512 B` lines up to the first `1 MiB` (`1,048,576 B`) valid-line prefix and dropping only trailing overflow bytes (`acli_telemetry_fallback_truncated_total`)** before atomically `unlinkat`ing the path, validating `HMAC-SHA256(fallback_mac_key)`, never logging raw parse failures, and stamping authoritative `acli.*` attributes

### Requirement: Closed Positive Attribute Allowlist, Three Privacy Tiers, and Four-Stage Pre-Write Rust DLP
